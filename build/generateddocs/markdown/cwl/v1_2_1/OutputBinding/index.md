
# OutputBinding (Schema)

`ogc.cwl.v1_2_1.OutputBinding` *v1.2.1*

Defines how to retrieve the output result from the command.

[*Status*](http://www.opengis.net/def/status): Under development

## Description

`OutputBinding` (CWL's `CommandOutputBinding`) describes how to generate an output parameter's value
from the files produced by a `CommandLineTool`'s execution.

The output value is generated by applying these operations, in this fixed order:

1. **`glob`**
2. **`loadContents`**
3. **`outputEval`**
4. `secondaryFiles`

## `glob`

Finds files or directories relative to the output directory using POSIX `glob(3)` pathname matching.
If an array of patterns is given, any file/directory matching any pattern in the array is found. If a
[CWLExpression](bblocks://ogc.cwl.v1_2_1.CWLExpression) is given, it must evaluate to a string or
array of strings, which are then used as one or more glob patterns. Only files/directories that
actually exist may be matched and returned.

A relative glob pattern (not starting with `/`) is resolved relative to the output directory; an
absolute pattern must still resolve to a path inside the output directory — it is an error for a glob
to resolve to a path outside it. A matched path that is a symlink takes the `basename` (and
`nameroot`/`nameext`) of the symlink itself, while its `location` may point at the symlink target,
implementation permitting. Because implementations may shut down the execution container before
globbing, glob patterns and expressions must not assume access to anything beyond the declared inputs
and outputs.

## `loadContents`

If `true`, the matched file (or each file in a matched array) must be a UTF-8 text file no larger than
64 KiB; the implementation reads its entire contents into the File object's `contents` field for use
by `outputEval`. A file larger than 64 KiB is a fatal error. A tool that needs to return a large
amount of structured data can instead write a `cwl.output.json`, which bypasses both `outputEval` and
the 64 KiB limit.

## `outputEval`

A [CWLExpression](bblocks://ogc.cwl.v1_2_1.CWLExpression) that computes the output value. If `glob`
was specified, `self` is the array of matched file objects (an empty array if none matched, or a
single-element array if exactly one matched); the process's exit code is available as
`runtime.exitCode`. If `loadContents` is `true`, the matched file's text is available via its
`contents` field, per the rules above.

## Examples

### Single glob pattern
Captures a single output file by name, adapted from a CWL conformance test that runs `cat` and
collects its output file.

#### json
```json
{
  "glob": "output.txt"
}

```

#### jsonld
```jsonld
{
  "@context": "https://ogcincubator.github.io/bblocks-cwl/build/annotated/cwl/v1_2_1/OutputBinding/context.jsonld",
  "glob": "output.txt"
}
```

#### ttl
```ttl
@prefix ns1: <https://w3id.org/cwl/cwl#CommandOutputBinding/> .

[] ns1:glob "output.txt" .


```


### Computed glob with loaded contents and outputEval
Uses a [CWLExpression](bblocks://ogc.cwl.v1_2_1.CWLExpression) to compute the glob pattern from
an input parameter, loads the matched file's contents (`loadContents`), and derives the final
output value from those contents with `outputEval`. `loadContents` and `outputEval` are not part
of this block's own schema but are accepted as additional properties.

#### json
```json
{
  "glob": "$(inputs.indir.basename)/*",
  "loadContents": true,
  "outputEval": "$(self[0].contents)"
}

```

#### jsonld
```jsonld
{
  "@context": "https://ogcincubator.github.io/bblocks-cwl/build/annotated/cwl/v1_2_1/OutputBinding/context.jsonld",
  "glob": "$(inputs.indir.basename)/*",
  "loadContents": true,
  "outputEval": "$(self[0].contents)"
}
```

#### ttl
```ttl
@prefix ns1: <https://w3id.org/cwl/cwl#CommandOutputBinding/> .

[] ns1:glob "$(inputs.indir.basename)/*" .


```
